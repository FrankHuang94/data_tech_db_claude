## A

### ACID

atomicity, consistency, isolation and durability: the guarantees that make database transactions safe. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### ADBC

Arrow Database Connectivity, a database client API that returns results as Arrow batches, a columnar counterpart to JDBC/ODBC. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Agent Bricks

Databricks' tooling to build, evaluate and automatically optimise AI agents on governed enterprise data. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Aggregate awareness

a query engine's ability to route a request to a smaller pre-built rollup table when that table can answer it. *See [Ch 14](02-pipelines-and-governance/ch14-semantic-layers-and-bi.md).*

### AI agent

A model-driven program that plans and calls tools, including data queries, to complete a task. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Analytics engineering

The discipline of applying software practices (version control, code review, CI, tests) to SQL data transformation. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Apache Arrow

A language-neutral, in-memory columnar data layout that lets tools share data without converting it. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Apache Avro

A row-oriented binary file and serialization format that embeds its schema and defines rules for reading data written under older schemas. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Apache Iceberg

An open table format created at Netflix that tracks table state through a tree of metadata and manifest files. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Apache ORC

Optimized Row Columnar, a columnar file format created in 2013 by Hortonworks with Facebook to speed up Hive. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Apache Parquet

The default open columnar file format for analytics, created by Twitter and Cloudera in 2013 using Dremel's nested-data encoding. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Apache Ranger

an open-source framework for defining and enforcing data access policies across Hadoop-era platforms such as Hive, HDFS and Kafka. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Apache Spark

A distributed data-processing engine created at UC Berkeley's AMPLab and the foundation of Databricks. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Apache XTable

an incubating Apache project that translates table metadata between Iceberg, Delta Lake and Hudi without copying data files. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Append-only log

An ordered sequence of records that is only ever appended to, with readers tracking their position by offset. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Approximate nearest neighbor

Similarity search that trades a little recall for large speed gains, using indexes such as HNSW. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### ARIES

IBM's 1992 write-ahead-logging recovery algorithm with analysis, redo and undo passes. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Arrow Flight

A gRPC-based protocol for streaming Arrow record batches between services without row-by-row serialization. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Attribute-based access control

a model that decides access at request time from attributes of the user, the data, the action and the context. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

## B

### B-tree

a shallow, wide, sorted tree of fixed-size pages used for indexes and tables; the common B+tree variant keeps all data in leaf pages linked left to right. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Backfill

Reprocessing historical data to fill gaps or apply corrected logic to past periods. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Binlog

MySQL's binary log of committed changes, used for replication and change data capture. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Bit-packing

storing integers using only the minimum number of bits their range requires. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Bitmap index

an index storing one bit-vector per distinct column value, suited to low-cardinality analytic filters. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Bloom filter

a compact probabilistic data structure that answers "definitely not present" or "maybe present" for a key. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### BM25

The standard keyword relevance-scoring function used by Lucene, Elasticsearch and OpenSearch. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Bring your own cloud

A deployment model (BYOC) in which a vendor's data plane runs inside the customer's own cloud account. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Broker

A Kafka server that stores partitions and serves producer writes and consumer reads. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Buffer pool

the database's own in-memory cache of data and index pages. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Business catalog

a tool for people to discover, understand and trust data through search, a business glossary and stewardship workflows (e.g., Collibra, Alation, Atlan). *See [Ch 08](01-data-systems-foundations/ch08-catalogs-and-metastores.md).*

## C

### CAP theorem

the result that a replicated system facing a network partition must choose between consistency and availability. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Capacity-based pricing

billing for reserved processing capacity rather than for data volume moved. *See [Ch 10](02-pipelines-and-governance/ch10-ingestion-and-integration.md).*

### Cardinality estimation

predicting how many rows each step of a query plan will produce. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Catalog federation

one catalog discovering, governing and querying tables that are registered in another catalog without copying them. *See [Ch 08](01-data-systems-foundations/ch08-catalogs-and-metastores.md).*

### Catalog-managed table

a Delta Lake table (4.1+) whose commits are ratified by its catalog rather than by the filesystem. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Change data capture

Reading a database's transaction log to emit each committed change as an event for downstream systems. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Checkpoint

a point at which a database flushes dirty pages so crash recovery can start from there instead of the log's beginning. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Clustered index

a table stored as a B-tree ordered by its primary key, with full rows in the leaves (as in InnoDB). *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Column chunk

The contiguous bytes of one column inside one Parquet row group, split into pages. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Column-level lineage

Tracing which upstream columns feed each downstream column, typically derived by parsing SQL. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Column-level security

a policy that blocks or masks specific columns depending on who is asking. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Columnar storage

storing each column's values contiguously so analytical queries read only the columns they need. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Compaction

a maintenance job that rewrites many small or delete-laden files into fewer, larger, often sorted files. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Compare-and-swap

an atomic operation that updates a value only if it still equals an expected value; the primitive behind table-format commits. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Composable data stack

building data systems from shared, interchangeable components such as Arrow, Velox and DataFusion. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Compute plane

The layer where data is actually processed; in Databricks it sits in the customer's cloud account (classic) or the vendor's (serverless). *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Conditional write

an object-store write that succeeds only if a precondition holds, such as the object not already existing. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Connector

code that extracts data from one source type (SaaS API, database, file) and emits standardized records to a destination. *See [Ch 10](02-pipelines-and-governance/ch10-ingestion-and-integration.md).*

### Connector SDK

a development kit for writing custom connectors that a vendor's managed runtime hosts and meters. *See [Ch 10](02-pipelines-and-governance/ch10-ingestion-and-integration.md).*

### Consensus

a protocol by which a group of replicas agrees on a single ordered log of operations despite crashes and message delays. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Consistent hashing

placing nodes and keys on a hash ring so adding or removing a node moves only a small share of keys. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Consumer group

A set of consumers that divide a topic's partitions among themselves, with the group tracking its own committed offsets. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Control plane

The vendor-hosted services that manage, schedule and govern work, separate from where data is processed. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Conversational analytics

natural-language question answering over governed data inside a BI tool or data platform. *See [Ch 14](02-pipelines-and-governance/ch14-semantic-layers-and-bi.md).*

### Copy-on-write

applying row-level changes by rewriting the affected data files in full, making writes costly and reads simple. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Covering index

an index that contains every column a query needs, so the table itself need not be read. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Credential vending

a catalog issuing short-lived storage credentials, scoped to one table's prefix, to an engine it has authorized. *See [Ch 08](01-data-systems-foundations/ch08-catalogs-and-metastores.md).*

### Cursor field

a column such as updated_at that a connector uses to find changed records. *See [Ch 10](02-pipelines-and-governance/ch10-ingestion-and-integration.md).*

### Cypher

Neo4j's declarative property-graph query language and the main basis for ISO GQL. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

## D

### Data catalog

The registry of data assets, owners, lineage and access policies that spans every layer of the stack. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Data classification

labelling data by type and sensitivity (for example, email address, card number, health data) so policies can act on it. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data clean room

an environment where two or more parties analyse combined data under agreed rules without seeing each other's rows. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data contract

A producer-owned, enforced agreement on a dataset's schema, semantics, quality rules and SLAs. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Data detection and response

monitoring of data access patterns to alert on and respond to unusual or malicious activity. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data diff

a row-by-row comparison of two versions of a table, used in CI or migrations to catch regressions before they ship. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data discovery

finding where data stores, and the sensitive data inside them, exist across an estate. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data downtime

a period when data is late, missing, wrong or otherwise unreliable, by analogy with application downtime. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data gravity

The tendency of large datasets to attract applications, compute and further data toward where they live. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Data inlining

DuckLake's technique of storing very small inserts, updates and deletes in the catalog database instead of writing new files. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Data lineage

the directed graph of how data flows from sources through transformations to consumers such as dashboards, models and indexes. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data loss prevention

controls that detect and block sensitive data leaving approved boundaries. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data metric function

a Snowflake function, scheduled on a table, that measures a quality metric such as row count, freshness or null count. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data mirroring

Continuous, vendor-managed replication of an operational database into an analytics platform (e.g., Fabric mirroring, Snowflake Postgres mirroring). *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Data observability

automated monitoring of dataset metadata (freshness, volume, schema, distribution, lineage) to detect, triage and explain data problems. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data security posture management

continuous discovery of sensitive data, who can access it and where it is exposed, ranked by risk. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data SLO

an internal service-level objective for a dataset's freshness, completeness or accuracy. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Data sovereignty

legal requirements that certain data be stored and processed within a particular jurisdiction. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Data subject access request

an individual's legal request to see the personal data an organisation holds about them. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Data test

an explicit assertion, such as not-null, unique or accepted values, run against production data after a build. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### dbt

Open-source framework that compiles SQL-plus-Jinja "models" into a dependency graph and runs them inside a warehouse or lakehouse. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### DBU

Databricks Unit, the normalised unit of processing per hour that Databricks meters and prices by workload SKU. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Declarative pipeline

A pipeline defined by the tables it should produce rather than the steps to run, e.g., Lakeflow Spark Declarative Pipelines. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Declarative query

A query that states the result wanted and leaves the execution method to the database optimizer, as in SQL. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Delete file

an Iceberg v2 file recording deleted rows either by file position or by column values. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Deletion vector

a compact bitmap marking which row positions in one data file are deleted, used by Delta Lake and Iceberg v3. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Delta checkpoint

a Parquet file summarising a Delta table's full state at one version so readers need not replay the whole log. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Delta encoding

compression that stores differences between consecutive values instead of the values themselves. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Delta Lake

Databricks' open table format: Parquet data files plus a JSON transaction log that gives ACID commits on object storage. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Delta log

the `_delta_log` directory of numbered JSON commit files that records every change to a Delta Lake table. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Delta Sharing

Open REST protocol (2021) that shares tables by handing recipients short-lived signed URLs to the underlying files; now OpenSharing. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Denormalization

Deliberately duplicating data across records to make common reads cheaper at the cost of harder updates. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Dictionary encoding

compression that replaces repeated values with small integer codes plus a lookup table. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Differential privacy

adding calibrated statistical noise to results so they reveal little about any single individual. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Dimension

an attribute such as region or fiscal quarter used to group or filter measures. *See [Ch 14](02-pipelines-and-governance/ch14-semantic-layers-and-bi.md).*

### Directed acyclic graph

A graph of tasks or models connected by one-way dependency edges with no cycles, used to determine run order. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Disaggregated storage

an architecture separating stateless compute from a shared storage service; in Aurora and Neon the storage consumes the database log. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Diskless Kafka

Kafka-compatible designs whose primary store is object storage and whose brokers are stateless (e.g., WarpStream, KIP-1150). *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Document database

A database that stores self-contained JSON-like records (documents), such as MongoDB. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### DPU-hour

AWS Glue's billing unit: one data processing unit of compute running for one hour. *See [Ch 10](02-pipelines-and-governance/ch10-ingestion-and-integration.md).*

### DuckLake

a lakehouse format from the DuckDB team that stores all table metadata in a SQL database and data in Parquet. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Durable execution

A runtime model that persists each workflow step so code resumes exactly where it stopped after crashes or long waits. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Dynamic data masking

rewriting sensitive values at query time (for example, showing j***@example.com) without changing the stored data. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Dynamic table

A Snowflake table defined by a query and a target lag that the engine refreshes automatically, incrementally where possible. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

## E

### ELT

Extract, load, transform: landing raw data first and transforming it inside the warehouse or lakehouse. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Embedding

A numeric vector produced by a model so that items with similar meaning lie close together. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Entity resolution

linking records and detections across systems to the same real-world person or thing. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Equality delete

a delete expressed as column values (for example id = 5), cheap for streaming writers but expensive for readers. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### ETL

Extract, transform, load: data is cleaned and reshaped on a separate system before it is loaded into the warehouse. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Event streaming

Moving events continuously between systems through a durable, partitioned, append-only log such as Apache Kafka. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Event time

The time an event actually occurred, as opposed to the processing time at which the system observed it. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Eventual consistency

a consistency model promising only that replicas converge once writes stop. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Exact data match

detecting sensitive data by comparing content against hashed values from a known reference table. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Exactly-once semantics

A pipeline guarantee that each event affects the final result exactly once despite retries, achieved via deduplication or transactions. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### EXPLAIN

the SQL command that shows the execution plan the optimizer chose, optionally with actual run-time statistics. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Exposure

A declared downstream consumer of dbt models (dashboard, ML model, application) recorded in the project graph. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### External consistency

the guarantee that transaction commit order matches real-time order across the whole system, as in Spanner. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### External location

A Unity Catalog object that binds a storage path to a credential so governed tables and files can live there. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

## F

### Fan-out

the number of child pointers held by each internal page of a tree index, which sets the tree's height. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Five pillars of data observability

Monte Carlo's framing of the signals to monitor: freshness, volume, schema, distribution and lineage. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Foreign key

A column whose values must match the primary key of another table, linking related rows. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Format-preserving encryption

encryption whose output keeps the format of the input, such as a 16-digit number staying 16 digits. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Fsync

the operating-system call that forces buffered writes for a file onto stable storage. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

## G

### Genie

Databricks' natural-language analytics agent that turns questions into governed SQL, extended as Genie One in 2026. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### GQL

Graph Query Language, the ISO/IEC 39075:2024 standard for querying property graphs, largely based on Cypher. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Graph traversal

Answering a query by following edges from node to node, with cost proportional to edges touched. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Group commit

making several concurrently committing transactions durable with a single log flush. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

## H

### Headless BI

a semantic layer decoupled from any single visualization tool and served to many consumers via APIs. *See [Ch 14](02-pipelines-and-governance/ch14-semantic-layers-and-bi.md).*

### Hidden partitioning

Iceberg's practice of deriving partition values from column transforms so queries filter on ordinary columns and never reference partitions. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Hive Metastore

Apache Hive's Thrift service backed by a relational database that records tables, columns and partitions; the first widely shared lakehouse catalog. *See [Ch 08](01-data-systems-foundations/ch08-catalogs-and-metastores.md).*

### Hot spot

a shard or key that receives disproportionate traffic and limits the throughput of the whole cluster. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### HTAP

Hybrid transactional/analytical processing: one system serving OLTP and OLAP workloads on fresh data (term coined by Gartner, 2014). *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Hudi timeline

Apache Hudi's ordered record of table actions (commits, compactions, cleans), each moving from requested to inflight to completed. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Hybrid logical clock

a timestamp combining physical clock time with a logical counter, used by CockroachDB and YugabyteDB to order events without special hardware. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

## I

### Iceberg REST catalog

the open HTTP API specification through which engines load, commit to and increasingly plan scans on Iceberg tables. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Idempotency

The property that running an operation more than once produces the same result as running it once. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Idempotent producer

A Kafka producer that stamps batches with sequence numbers so broker-side deduplication makes retries harmless. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Impact analysis

using downstream lineage to find every asset and owner affected by a proposed or actual change. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### In-sync replicas

### Static data masking

permanently replacing sensitive values in a copy of the data, typically for test or vendor use. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Stream processing

Continuous computation such as filters, joins and aggregations over unbounded event streams. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Streaming database

A database that keeps SQL materialized views continuously up to date from incoming streams (e.g., RisingWave, Materialize). *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

## T

### Table metadata file

Iceberg's JSON root file holding a table's schemas, partition specs, properties and snapshot list; the catalog points to the current one. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Tag-based policy

an access or masking policy attached to a tag, so it applies automatically to every object carrying that tag. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Technical catalog

the on-path service that resolves a table name to its current metadata, arbitrates atomic commits and enforces access policy for every engine. *See [Ch 08](01-data-systems-foundations/ch08-catalogs-and-metastores.md).*

### Tender offer

An offer to buy existing shares from employees and holders, often used by private companies to provide liquidity. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

### Text-to-SQL

an LLM translating a natural-language question directly into a SQL query. *See [Ch 14](02-pipelines-and-governance/ch14-semantic-layers-and-bi.md).*

### TFRecord

TensorFlow's sequential record-stream file format for training examples. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Tiered storage

Offloading older log segments from broker disks to object storage while keeping recent data local (Kafka KIP-405). *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Time travel

querying a table as it existed at an earlier snapshot, version or timestamp. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Time-series database

A database tuned for time-stamped, append-mostly measurements and window aggregations. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Timestamp oracle

a central service that issues strictly increasing transaction timestamps, as in Percolator and TiDB's Placement Driver. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Tokenization

replacing a sensitive value with a surrogate token that can be mapped back only by a privileged service or key. *See [Ch 15](02-pipelines-and-governance/ch15-governance-security-privacy.md).*

### Tombstone

a marker written in an LSM-tree to record a deletion until compaction removes the key. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Topic

A named stream in Kafka, made up of one or more partitions. *See [Ch 11](02-pipelines-and-governance/ch11-streaming-and-event-platforms.md).*

### Trigger-based CDC

Change data capture that uses database triggers to copy each change into a shadow table, at a cost to every write. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### TrueTime

Google's clock API, backed by GPS and atomic clocks, that returns a bounded interval of possible current times. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Two-phase commit

an atomic-commit protocol in which a coordinator collects prepare votes and then issues commit, blocking if it fails mid-protocol. *See [Ch 04](01-data-systems-foundations/ch04-distributed-databases.md).*

### Two-phase locking

a pessimistic concurrency protocol that acquires locks as needed and releases them only after commit. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

## U

### Undo log

storage holding prior images of changed rows, used for rollback and for reading older snapshots (Oracle, InnoDB). *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### UniForm

Delta Lake's Universal Format feature, which writes Iceberg (and Hudi) metadata alongside the Delta log so other engines can read one copy of data. *See [Ch 07](01-data-systems-foundations/ch07-open-table-formats.md).*

### Unit test

a test of transformation logic against mock input rows, run in development or CI rather than on production data. *See [Ch 13](02-pipelines-and-governance/ch13-data-quality-observability-lineage.md).*

### Unity Catalog

Databricks' governance catalog for tables, files, models and functions, handling permissions, lineage, audit and credential vending. *See [Ch 25](04-company-deep-dives/ch25-databricks.md).*

## V

### Vacuum

PostgreSQL's background process that reclaims space from dead row versions. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Valkey

The Linux Foundation's BSD-licensed fork of Redis 7.2.4, created in March 2024. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Vector index

A data structure for fast approximate nearest-neighbor search over embeddings. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Vectorized execution

query processing that passes cache-sized batches of values between operators instead of one row at a time. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Virtual data environment

SQLMesh's layer of views over versioned physical tables that lets dev and CI environments reuse unchanged production data. *See [Ch 12](02-pipelines-and-governance/ch12-transformation-and-orchestration.md).*

### Virtual warehouse

Snowflake's independently sized, stateless compute cluster that reads shared table data. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Volcano iterator model

the classic tuple-at-a-time execution design in which each operator pulls one row from its child via next(). *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Volcano model

row-at-a-time query execution in which each operator pulls rows from its child through a next() call. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Vortex

A compressed columnar file, memory and IPC format created by SpiralDB and hosted since 2025 by the LF AI & Data Foundation. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

## W

### Watermark

A stream processor's running estimate that all events up to a given event time have arrived, used to decide when to emit window results. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### WebDataset

A training-data format that packs samples into tar shards so reads stay sequential while shards are shuffled. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Wide-column store

A database of sparse rows grouped by partition key and sorted by clustering key, descended from Google Bigtable. *See [Ch 02](01-data-systems-foundations/ch02-data-models.md).*

### Workload

The pattern in which software reads and writes data (size, frequency, latency and concurrency of operations). *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Write amplification

the ratio of bytes physically written to storage to bytes the application logically wrote. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Write skew

an anomaly where two transactions read overlapping data, write different rows and together violate a rule neither violates alone. *See [Ch 03](01-data-systems-foundations/ch03-database-internals.md).*

### Write-ahead log

A sequential log of changes made durable before a database confirms a transaction; used for crash recovery, replication and CDC. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

## Z

### Zero-copy

Handing data between components by sharing the same memory buffers instead of copying or converting them. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*

### Zero-copy data sharing

Granting another account or organization query access to data in place, without duplicating it. *See [Ch 09](02-pipelines-and-governance/ch09-pipeline-patterns.md).*

### Zero-ETL

Vendor-managed replication from an operational database into an analytical system that hides the pipeline from the user. *See [Ch 01](01-data-systems-foundations/ch01-data-stack-map.md).*

### Zone map

per-chunk min/max statistics an engine checks to skip data that cannot match a filter. *See [Ch 05](01-data-systems-foundations/ch05-analytical-engines.md).*

### Zstandard

A general-purpose compression codec (zstd) that gives higher ratios than Snappy at similar decompression speed. *See [Ch 06](01-data-systems-foundations/ch06-file-formats.md).*
