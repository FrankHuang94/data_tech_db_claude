- **Read-after-write consistency** — a guarantee that a successful write is immediately visible to every later read and listing; S3 has provided it since December 2020. (ch24)
- **S3 Express One Zone** — AWS's single-Availability-Zone, low-latency S3 storage class that uses directory buckets, often used as a hot tier for tables and training data. (ch24)
- **Request pricing** — per-call charges for object-storage operations such as PUT, GET and LIST, which make many small files expensive. (ch24)
- **RAPIDS** — NVIDIA's open-source suite of CUDA libraries (cuDF, cuML, cuVS and others) for GPU data science and data processing. (ch24)
- **cuDF** — the RAPIDS GPU dataframe library, whose pandas accelerator mode runs pandas code on GPUs with CPU fallback. (ch24)
- **cuVS** — the RAPIDS library for building and searching vector indexes on GPUs, integrated into Faiss, Milvus and OpenSearch. (ch24)
- **RAPIDS Accelerator for Apache Spark** — an NVIDIA plugin that replaces Spark SQL and DataFrame operators with GPU versions without user code changes. (ch24)
- **Project Aether** — NVIDIA tooling, announced at GTC 2025, that qualifies, tests and tunes Spark jobs for GPU acceleration. (ch24)
- **GPUDirect Storage** — NVIDIA technology that moves data from storage directly into GPU memory by DMA, bypassing a copy through host DRAM. (ch24)
- **cuObject** — NVIDIA libraries that move S3 object payloads over RDMA into GPU or host memory while keeping the S3 control path on HTTP. (ch24)
- **Arithmetic intensity** — the number of operations a job performs per byte it moves; it determines whether the job is compute-bound or bandwidth-bound. (ch24)
- **Cache tier** — fast local storage (SSD or memory) that holds a hot working set in front of slower object storage. (ch24)
- **Egress fee** — a cloud provider's per-GB charge for data leaving its network or region. (ch24)
- **Sovereign cloud** — a cloud region operated under local jurisdiction, often by locally resident staff, to meet data-sovereignty rules. (ch24)
- **Cloud repatriation** — moving workloads or data from public cloud back to on-premises or private infrastructure. (ch24)
- **Erasure coding** — storing data as fragments plus parity so it survives failures with less capacity overhead than full replication. (ch24)
