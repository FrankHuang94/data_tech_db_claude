- **Role-based access control** — a model in which permissions are granted to roles and users receive access by being assigned roles. (ch15)
- **Attribute-based access control** — a model that decides access at request time from attributes of the user, the data, the action and the context. (ch15)
- **Row-level security** — a policy that silently filters which rows of a table a given user can see. (ch15)
- **Column-level security** — a policy that blocks or masks specific columns depending on who is asking. (ch15)
- **Dynamic data masking** — rewriting sensitive values at query time (for example, showing j***@example.com) without changing the stored data. (ch15)
- **Static data masking** — permanently replacing sensitive values in a copy of the data, typically for test or vendor use. (ch15)
- **Tag-based policy** — an access or masking policy attached to a tag, so it applies automatically to every object carrying that tag. (ch15)
- **Policy engine** — software that evaluates access rules and returns allow, deny, filter or mask decisions for enforcement points. (ch15)
- **Open Policy Agent** — a CNCF graduated, general-purpose policy engine that evaluates rules written in the Rego language. (ch15)
- **Apache Ranger** — an open-source framework for defining and enforcing data access policies across Hadoop-era platforms such as Hive, HDFS and Kafka. (ch15)
- **Data classification** — labelling data by type and sensitivity (for example, email address, card number, health data) so policies can act on it. (ch15)
- **Data discovery** — finding where data stores, and the sensitive data inside them, exist across an estate. (ch15)
- **Exact data match** — detecting sensitive data by comparing content against hashed values from a known reference table. (ch15)
- **Luhn checksum** — a check-digit algorithm used to validate candidate payment-card numbers and reject most random digit strings. (ch15)
- **Named-entity recognition** — machine learning that tags names, places, organisations and similar entities in free text. (ch15)
- **Entity resolution** — linking records and detections across systems to the same real-world person or thing. (ch15)
- **Data security posture management** — continuous discovery of sensitive data, who can access it and where it is exposed, ranked by risk. (ch15)
- **Shadow data** — copies of data that sit outside governed, catalogued systems, such as exports, snapshots and scratch buckets. (ch15)
- **Data loss prevention** — controls that detect and block sensitive data leaving approved boundaries. (ch15)
- **Tokenization** — replacing a sensitive value with a surrogate token that can be mapped back only by a privileged service or key. (ch15)
- **Format-preserving encryption** — encryption whose output keeps the format of the input, such as a 16-digit number staying 16 digits. (ch15)
- **Pseudonymisation** — processing personal data so it cannot be attributed to a person without separately held information; still personal data under GDPR. (ch15)
- **Differential privacy** — adding calibrated statistical noise to results so they reveal little about any single individual. (ch15)
- **Data clean room** — an environment where two or more parties analyse combined data under agreed rules without seeing each other's rows. (ch15)
- **Data subject access request** — an individual's legal request to see the personal data an organisation holds about them. (ch15)
- **Right to erasure** — the GDPR right to have personal data deleted in defined circumstances (Article 17). (ch15)
- **Purpose limitation** — the principle that personal data be collected and used only for specified, compatible purposes. (ch15)
- **Data sovereignty** — the principle that data is subject to the laws of the place where it is stored or where its subjects reside. (ch15)
- **Model Context Protocol** — an open protocol for connecting AI agents to tools and data sources. (ch15)
- **Role explosion** — the proliferation of narrowly scoped roles that occurs when RBAC is used to express many combinations of sensitivity, region and purpose. (ch15)
- **Data detection and response** — monitoring of data access patterns to alert on and respond to unusual or malicious activity. (ch15)
