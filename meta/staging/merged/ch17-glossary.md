- **Unstructured data** — content without a predefined schema, such as documents, email, images, audio and video. (ch17)
- **Dark data** — stored data whose content and business value the organisation does not know. (ch17)
- **Document parsing** — converting a file into ordered text plus structure such as headings, tables and page references. (ch17)
- **Optical character recognition** — converting images of text into machine-readable characters, usually with a confidence score for each word (OCR). (ch17)
- **Layout analysis** — detecting a page's regions (headings, paragraphs, tables, figures) and how they relate. (ch17)
- **Reading order** — the sequence in which a human would read a page's text blocks, which parsers must reconstruct from glyph positions. (ch17)
- **Vision-language model** — a model that takes images and text as input, used to parse rendered page images directly into Markdown or JSON (VLM). (ch17)
- **Chunking** — splitting documents into retrievable units, each of which gets its own embedding. (ch17)
- **Chunk overlap** — text repeated at the boundary of adjacent chunks so that context is not lost at the split. (ch17)
- **Fixed-size chunking** — splitting text every N tokens regardless of document structure. (ch17)
- **Recursive chunking** — splitting by progressively finer separators (paragraph, sentence, word) until chunks fit a size limit. (ch17)
- **Semantic chunking** — placing chunk boundaries where the embedding similarity between adjacent sentences drops. (ch17)
- **Section-aware chunking** — splitting along the headings, pages and tables recovered by a layout parser. (ch17)
- **Late chunking** — embedding a whole document with a long-context model first, then pooling token vectors into chunk vectors. (ch17)
- **Access control list** — the list of users and groups permitted to access a resource, and with what rights (ACL). (ch17)
- **ACL propagation** — carrying a source document's permissions onto every derived chunk, vector and cached answer. (ch17)
- **Permission-aware retrieval** — filtering retrieval candidates by the caller's identity and the stored ACLs before ranking. (ch17)
- **Content hash** — a fingerprint of a file's bytes used to detect changes and duplicates during sync. (ch17)
- **Personally identifiable information** — data that can identify an individual, such as names, IDs or contact details (PII). (ch17)
