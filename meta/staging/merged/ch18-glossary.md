- **Embedding** — A learned vector representation in which similar content lies close together. (ch18)
- **Contrastive learning** — Training that pulls matching pairs (e.g., question and answer passage) together in vector space and pushes non-matching pairs apart. (ch18)
- **Cosine similarity** — Similarity between two vectors measured by the angle between them; equal to the dot product for unit-length vectors. (ch18)
- **k-nearest neighbors** — Exact search for the k stored vectors closest to a query, comparing against every vector. (ch18)
- **Approximate nearest neighbor** — Similarity search that trades a little recall for large speed and cost gains, using indexes such as HNSW, IVF-PQ or DiskANN. (ch18)
- **Recall at k** — The share of the true k nearest neighbours that an approximate index actually returns. (ch18)
- **HNSW** — Hierarchical Navigable Small World, a layered proximity-graph vector index searched by greedy descent from sparse to dense layers. (ch18)
- **IVF** — Inverted file index: clusters vectors with k-means and searches only the clusters nearest the query (set by nprobe). (ch18)
- **Product quantization** — Vector compression that splits each vector into slices and stores each slice as an index into a learned codebook. (ch18)
- **Codebook** — The learned set of representative sub-vectors that product quantization codes point into. (ch18)
- **IVF-PQ** — A vector index combining IVF clustering with product-quantized vectors, standard for billion-scale search on one machine or GPU. (ch18)
- **Scalar quantization** — Storing each vector coordinate in fewer bits, such as int8 instead of float32, for a 4x size cut. (ch18)
- **Binary quantization** — Storing one bit per vector dimension, a 32x size cut, usually followed by rescoring. (ch18)
- **Matryoshka embedding** — An embedding trained so its leading dimensions form a usable shorter embedding, allowing truncation. (ch18)
- **Rescoring** — Re-ranking candidates found with compressed vectors using their full-precision vectors. (ch18)
- **DiskANN** — Microsoft's SSD-resident graph vector index that keeps compressed vectors in DRAM and full vectors plus graph on flash. (ch18)
- **Vamana** — The single-layer graph-construction algorithm behind DiskANN, which keeps some long edges to shorten searches. (ch18)
- **CAGRA** — NVIDIA's GPU-optimised graph vector index, part of the cuVS library. (ch18)
- **Pre-filtering** — Applying metadata filters before vector search, exact but able to fragment graph indexes. (ch18)
- **Post-filtering** — Applying metadata filters after vector search, simple but able to return too few results. (ch18)
- **Hybrid search** — Combining keyword (BM25) and vector retrieval, usually followed by a reranker. (ch18)
- **Vector database** — A database built primarily to store, index and query embeddings with metadata filters. (ch18)
- **ScaNN** — Google's vector search method using anisotropic quantization, used in AlloyDB and Vertex AI Vector Search. (ch18)
- **SPANN** — Microsoft's cluster-based billion-scale vector index with centroids in memory and posting lists on disk. (ch18)
- **SPFresh** — An update-friendly extension of SPANN that rebalances clusters in place; basis of turbopuffer's index. (ch18)
- **MTEB** — Massive Text Embedding Benchmark, the standard public leaderboard for embedding models (extended as MMTEB). (ch18)
