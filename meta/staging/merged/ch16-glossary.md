- **Token** — The sub-word unit a language model reads and predicts; English text averages roughly four characters per token. (ch16)
- **Tokenization** — Converting text into integer token IDs from a fixed vocabulary before training or inference. (ch16)
- **Pretraining** — Training a model to predict the next token over a very large, general corpus such as filtered web text. (ch16)
- **Post-training** — The stages after pretraining (supervised fine-tuning, preference tuning, reinforcement learning) that turn a base model into an assistant. (ch16)
- **Data curation** — Extracting, filtering, deduplicating, quality-scoring and cleaning raw data into training-ready form. (ch16)
- **MinHash** — A hashing technique that cheaply estimates set similarity between documents, used for near-duplicate removal at web scale. (ch16)
- **Quality classifier** — A small model that scores documents for training value so only high-scoring text is kept. (ch16)
- **PII** — Personally identifiable information, such as names, emails and ID numbers, that must be removed or access-controlled. (ch16)
- **Synthetic data** — Training data generated by models rather than collected from people or the web. (ch16)
- **Supervised fine-tuning** — Training a model on example prompts paired with ideal responses (SFT). (ch16)
- **Reward model** — A model trained on human rankings of outputs that scores new outputs during reinforcement learning. (ch16)
- **Reinforcement learning from human feedback** — Tuning a model with reinforcement learning against a reward learned from human preference rankings (RLHF). (ch16)
- **Reinforcement learning from AI feedback** — RLHF in which a model, guided by written principles, produces the preference labels (RLAIF). (ch16)
- **Direct preference optimization** — A post-training method that learns directly from chosen/rejected answer pairs without a separate reward model (DPO). (ch16)
- **Preference data** — Pairs or rankings of model outputs labeled by which is better, used for RLHF or DPO. (ch16)
- **RL environment** — A sandboxed replica of a task, website or software system in which an AI agent acts and is automatically scored. (ch16)
- **Verifiable reward** — A reinforcement-learning reward computed by an automatic check, such as unit tests passing or a math answer matching. (ch16)
- **LLM judge** — A language model used to grade other models' outputs against a rubric. (ch16)
- **Red-teaming** — Adversarial human or automated testing to find unsafe or unintended model behavior. (ch16)
- **Context engineering** — Choosing, on every model call, which instructions, retrieved data, tool results and history enter the model's context window. (ch16)
- **Data flywheel** — A loop in which product usage generates data (logs, traces, feedback) that improves the product and attracts more usage. (ch16)
- **Data poisoning** — Inserting malicious examples into training or retrieval data to implant unwanted model behavior. (ch16)
- **Model checkpoint** — A saved snapshot of model weights and optimizer state used to resume, roll back or audit training. (ch16)
- **Data versioning** — Recording immutable, addressable versions of datasets (e.g., lakeFS commits, table snapshots) so runs can be reproduced. (ch16)
- **Trace** — A record of one AI or agent run: prompt, retrieved context, tool calls, outputs and outcome. (ch16)
