- **Schema linking** — selecting the relevant tables, columns and joins from a large schema before an LLM generates SQL. (ch22)
- **Self-correction loop** — executing or dry-running generated SQL and feeding errors and sanity-check failures back to the model to repair the query. (ch22)
- **Execution accuracy** — a text-to-SQL benchmark metric: the share of questions whose generated SQL returns the same result as the reference query. (ch22)
- **Spider 2.0** — a 2024–2025 text-to-SQL benchmark of 632 real enterprise workflow tasks on large cloud schemas, where top 2025 systems solved about 21%. (ch22)
- **BIRD benchmark** — a text-to-SQL benchmark with large, messy databases and external-knowledge hints, with a human baseline of about 93% execution accuracy. (ch22)
- **MCP server** — a service that wraps one system and exposes tools, resources and prompts to AI agents over the Model Context Protocol. (ch22)
- **Agentic AI Foundation** — the Linux Foundation directed fund, co-founded by Anthropic, Block and OpenAI, that has governed MCP since December 2025. (ch22)
- **Agent2Agent protocol** — an open protocol (A2A), launched by Google in 2025 and now at the Linux Foundation, that lets AI agents delegate tasks to other agents. (ch22)
- **Prompt injection** — malicious instructions embedded in content an LLM reads, causing it to act against its user. (ch22)
- **Lethal trifecta** — the risky combination, in one agent, of access to private data, exposure to untrusted content and a channel to send data out. (ch22)
- **Identity propagation** — passing the end user's identity through every hop so downstream systems enforce that user's permissions rather than a service account's. (ch22)
- **On-behalf-of flow** — an OAuth token exchange in which a service or agent obtains a token to act for a specific user. (ch22)
- **Agentic identity** — treating an AI agent as a distinct, auditable principal whose rights never exceed those of the user it serves. (ch22)
- **Agent memory** — information an AI agent stores outside its context window and recalls in later steps or sessions. (ch22)
- **Database branching** — creating an instant, copy-on-write fork of a database for testing, previews or agent work. (ch22)
- **Scale-to-zero** — releasing all compute for an idle database or service so it costs only storage until the next request. (ch22)
