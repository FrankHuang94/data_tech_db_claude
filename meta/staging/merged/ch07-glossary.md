- **Open table format** — an openly governed metadata layer and commit protocol that turns a collection of files on object storage into a transactional table with snapshots and schema evolution. (ch07)
- **Snapshot isolation** — a guarantee that each reader sees one consistent committed version of the data, unaffected by writes in progress. (ch07)
- **Time travel** — querying a table as it existed at an earlier snapshot, version or timestamp. (ch07)
- **Table metadata file** — Iceberg's JSON root file holding a table's schemas, partition specs, properties and snapshot list; the catalog points to the current one. (ch07)
- **Manifest list** — an Iceberg file listing the manifests that make up one snapshot, with partition-range summaries used to skip manifests. (ch07)
- **Manifest** — an Iceberg Avro file listing data or delete files with their partition values and per-column statistics. (ch07)
- **Delta log** — the `_delta_log` directory of numbered JSON commit files that records every change to a Delta Lake table. (ch07)
- **Delta checkpoint** — a Parquet file summarising a Delta table's full state at one version so readers need not replay the whole log. (ch07)
- **Hudi timeline** — Apache Hudi's ordered record of table actions (commits, compactions, cleans), each moving from requested to inflight to completed. (ch07)
- **Hidden partitioning** — Iceberg's practice of deriving partition values from column transforms so queries filter on ordinary columns and never reference partitions. (ch07)
- **Partition evolution** — changing a table's partitioning scheme for new data without rewriting existing files. (ch07)
- **Schema evolution** — safely adding, dropping, renaming, reordering or widening columns over a table's life without rewriting data. (ch07)
- **Compare-and-swap** — an atomic operation that updates a value only if it still equals an expected value; the primitive behind table-format commits. (ch07)
- **Optimistic concurrency control** — a scheme where writers work without locks and validate at commit time, retrying if another writer committed first. (ch07)
- **Copy-on-write** — applying row-level changes by rewriting the affected data files in full, making writes costly and reads simple. (ch07)
- **Merge-on-read** — applying row-level changes by writing separate delete or change records that readers merge at query time until compaction. (ch07)
- **Delete file** — an Iceberg v2 file recording deleted rows either by file position or by column values. (ch07)
- **Equality delete** — a delete expressed as column values (for example id = 5), cheap for streaming writers but expensive for readers. (ch07)
- **Deletion vector** — a compact bitmap marking which row positions in one data file are deleted, used by Delta Lake and Iceberg v3. (ch07)
- **Small-files problem** — the slowdown and overhead caused when a table accumulates many undersized data files, typically from frequent streaming commits. (ch07)
- **Compaction** — a maintenance job that rewrites many small or delete-laden files into fewer, larger, often sorted files. (ch07)
- **Snapshot expiration** — removing table snapshots older than a retention window so files they alone reference can be physically deleted. (ch07)
- **Orphan file** — a file in a table's storage location that no snapshot references, typically left by a failed or abandoned write. (ch07)
- **Catalog-managed table** — a Delta Lake table (4.1+) whose commits are ratified by its catalog rather than by the filesystem. (ch07)
- **Iceberg REST catalog** — the open HTTP API specification through which engines load, commit to and increasingly plan scans on Iceberg tables. (ch07)
- **UniForm** — Delta Lake's Universal Format feature, which writes Iceberg (and Hudi) metadata alongside the Delta log so other engines can read one copy of data. (ch07)
- **Apache XTable** — an incubating Apache project that translates table metadata between Iceberg, Delta Lake and Hudi without copying data files. (ch07)
- **DuckLake** — a lakehouse format from the DuckDB team that stores all table metadata in a SQL database and data in Parquet. (ch07)
- **Data inlining** — DuckLake's technique of storing very small inserts, updates and deletes in the catalog database instead of writing new files. (ch07)
- **Puffin file** — Iceberg's file format for auxiliary blobs such as statistics sketches and v3 deletion vectors. (ch07)
- **Conditional write** — an object-store write that succeeds only if a precondition holds, such as the object not already existing. (ch07)
- **Row lineage** — Iceberg v3 tracking of a stable row ID and last-updated sequence number for each row. (ch07)
- **Lakehouse** — an architecture that provides warehouse-grade management and performance over open file and table formats on object storage. (ch07)
- **ACID** — atomicity, consistency, isolation and durability: the guarantees that make database transactions safe. (ch07)
- **LSM-tree** — a log-structured merge tree, a write-optimised structure that buffers writes and merges sorted runs in the background. (ch07)
- **Parquet** — the dominant open columnar file format for analytics, used beneath all major table formats. (ch07)
- **Object storage** — flat, HTTP-accessed storage of immutable objects addressed by key, such as Amazon S3. (ch07)
