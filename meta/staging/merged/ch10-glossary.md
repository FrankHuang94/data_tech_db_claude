- **Connector** — code that extracts data from one source type (SaaS API, database, file) and emits standardized records to a destination. (ch10)
- **Change data capture** — reading a database's transaction log to capture inserts, updates and deletes as they happen. (ch10)
- **Backfill** — the initial historical load of a source before incremental syncs begin. (ch10)
- **Incremental sync** — fetching only the records that changed since the last successful sync. (ch10)
- **Cursor field** — a column such as updated_at that a connector uses to find changed records. (ch10)
- **State store** — where a pipeline records its progress (cursor values, log offsets) so it can resume without gaps or duplicates. (ch10)
- **Schema drift** — unplanned changes in a source's columns or data types that a pipeline must detect and handle. (ch10)
- **Schema registry** — a service that stores versioned schemas and checks whether changes are compatible. (ch10)
- **Idempotency** — the property that repeating an operation, such as a retried load, gives the same result as doing it once. (ch10)
- **Rate limit** — a cap on API calls per time window imposed by a source system. (ch10)
- **Monthly active rows** — Fivetran's billing unit: distinct rows inserted, updated or deleted per month, counted per connection. (ch10)
- **Informatica Processing Unit** — Informatica's pre-paid, pooled consumption unit that can be spent across IDMC services. (ch10)
- **DPU-hour** — AWS Glue's billing unit: one data processing unit of compute running for one hour. (ch10)
- **Capacity-based pricing** — billing for reserved processing capacity rather than for data volume moved. (ch10)
- **Connector SDK** — a development kit for writing custom connectors that a vendor's managed runtime hosts and meters. (ch10)
- **Singer** — an open specification for "taps" (sources) and "targets" (destinations) that exchange JSON records; the basis of Meltano. (ch10)
- **iPaaS** — integration platform as a service, used mainly to connect operational applications through APIs and events. (ch10)
- **ELT** — extract, load, then transform inside the destination warehouse or lakehouse. (ch10)
- **Reverse ETL** — syncing modeled warehouse data back into operational applications such as CRM. (ch10)
