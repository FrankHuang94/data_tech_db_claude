- **MLOps** — practices and tools that make the machine-learning lifecycle (data, features, training, registry, serving, monitoring) repeatable, governed and monitored. (ch21)
- **LLMOps** — MLOps adapted to LLM applications, managing prompts, traces, evaluations, guardrails and gateways instead of mainly model weights. (ch21)
- **Feature store** — a system that defines model features once and serves consistent values to both training and online inference. (ch21)
- **Offline store** — the part of a feature store that keeps full timestamped feature history, usually lakehouse tables, for building training sets. (ch21)
- **Online store** — the part of a feature store that keeps the latest feature values per entity in a low-latency key-value database for inference. (ch21)
- **Point-in-time join** — a join that attaches to each training label the most recent feature values known at the label's timestamp, preventing leakage. (ch21)
- **Training-serving skew** — a mismatch between the feature values a model saw in training and those it receives in production. (ch21)
- **Data leakage** — information that would not be available at prediction time entering training data and inflating offline accuracy. (ch21)
- **Experiment tracking** — logging each training run's parameters, metrics, code version and artifacts so runs can be compared and reproduced. (ch21)
- **Model registry** — a catalog of model versions with lineage, lifecycle stages and approvals used to promote models to production. (ch21)
- **Data drift** — a change in the distribution of live model inputs relative to the training data. (ch21)
- **LLM trace** — a record of every step, token count, latency and cost in a single LLM or agent request. (ch21)
- **LLM evaluation** — systematic scoring of LLM application outputs, offline on curated test sets or online on sampled production traffic. (ch21)
- **LLM-as-judge** — using a language model to grade another model's output against a rubric, calibrated against human labels. (ch21)
- **Golden set** — a curated, versioned set of test inputs with reference answers used for regression-testing an AI application. (ch21)
- **Guardrails** — input and output checks that block prompt injection, data leakage or unsafe and off-policy LLM responses. (ch21)
- **AI gateway** — a proxy in front of multiple model providers that handles routing, failover, credentials, rate limits, caching and spend caps. (ch21)
- **PagedAttention** — vLLM's technique of storing the attention key-value cache in fixed-size pages, like virtual memory, to raise GPU utilisation. (ch21)
