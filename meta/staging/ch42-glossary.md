- **Navigational database** — A database in which programs follow stored pointers from record to record to find data, as in IMS and CODASYL systems. (ch42)
- **Hierarchical database** — A navigational database that stores records as parent-child trees, such as IBM IMS. (ch42)
- **CODASYL** — The 1960s–70s industry committee whose network-model specification standardised pointer-linked databases such as IDMS. (ch42)
- **SQL** — Structured Query Language, the declarative query language that came out of IBM's System R and was first standardised by ANSI in 1986. (ch42)
- **Data warehouse** — A separate database built for analysis and loaded from operational systems, so reporting does not slow transactions. (ch42)
- **Enterprise data warehouse** — Inmon's single, normalised, company-wide warehouse that acts as the hub feeding departmental data marts. (ch42)
- **Data mart** — A subject-specific subset of warehouse data serving one department or business process. (ch42)
- **Star schema** — A warehouse design with a central fact table of measurements surrounded by dimension tables such as date, product and store. (ch42)
- **Dimensional modeling** — Kimball's method of designing warehouses as star schemas built per business process and linked by conformed dimensions. (ch42)
- **Conformed dimension** — A dimension, such as date or product, defined once and shared with the same meaning across several fact tables. (ch42)
- **Data warehouse appliance** — Database software sold pre-installed on purpose-built hardware as one system, as Teradata and Netezza did. (ch42)
- **NoSQL** — The umbrella term, popular from 2009, for non-relational databases such as key-value, document, wide-column and graph stores. (ch42)
- **Apache Hadoop** — The open-source distributed file system (HDFS) and MapReduce framework modelled on Google's GFS and MapReduce papers. (ch42)
- **HDFS** — The Hadoop Distributed File System, which stores large files as replicated blocks on the local disks of cluster servers. (ch42)
- **MapReduce** — A programming model from Google (2004) that processes large datasets in parallel as a map step followed by a reduce step. (ch42)
- **Data lake** — A store of raw files in many formats, kept cheaply and structured only when read. (ch42)
- **Data swamp** — A data lake that has become unusable because it lacks metadata, quality controls and governance. (ch42)
- **Modern data stack** — The 2016–2023 pattern of assembling single-purpose cloud tools (ingestion, transformation, BI) around a cloud data warehouse. (ch42)
- **Perpetual licence** — A one-time software licence fee that grants indefinite use, usually followed by annual maintenance payments. (ch42)
- **Consumption pricing** — Billing by measured usage, such as credits, compute-seconds or terabytes scanned, instead of seats or licences. (ch42)
- **What Goes Around Comes Around** — Stonebraker and Hellerstein's 2005 essay (with a 2024 sequel by Stonebraker and Pavlo) arguing that the relational model repeatedly absorbs challenger data models. (ch42)
